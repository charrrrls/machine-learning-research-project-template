# 复现与发布说明

目录组织的目标，是让读者能从环境和输入数据，走到论文中的结果。文件夹名字可以不同，但每一步的实现、参数和输入输出应当能找到。

## README 应交代的内容

1. **项目与论文**：方法解决什么问题，论文链接、主要贡献和一张必要的方法图。
2. **环境**：Python 与关键依赖版本；需要 GPU 时说明已验证的 CUDA 与硬件条件。
3. **数据**：原始来源、获取条件、解压后的结构、预处理和固定划分。
4. **最小运行**：给一条真实可运行的轻量示例，并说明输入、预期输出和保存位置。
5. **主要实验**：给出主实验、基线、消融的配置路径和运行命令。
6. **评价与汇总**：指标定义、数值单位、种子、checkpoint 选择方式与结果聚合规则。
7. **参考结果与成本**：列出参考数值，交代运行所用条件以及耗时的测量范围。
8. **许可与引用**：说明原创内容与第三方实现的来源，提供论文引用信息。

环境文件选适合项目的一套即可，例如 `requirements.txt`、`environment.yml` 或带依赖声明的 `pyproject.toml`；不需要为了显得齐全同时维护三份。

## 文件分别负责什么

| 位置 | 职责 | 应避免的混淆 |
|---|---|---|
| `src/` | 可复用的算法、模型、数据和指标实现 | 同一函数复制进多个实验脚本 |
| `scripts/` | 解析参数、连接处理步骤、启动实验 | 把整套算法隐藏在启动脚本中 |
| `configs/` | 可公开的超参数、种子、数据集设置 | 写入密码或只对一台机器有效的绝对路径 |
| `analysis/` | 从运行记录汇总统计与论文图表 | 手工改表后丢失原始数值来源 |
| `tests/` | 验证核心算法、指标和最短流程 | 将完整训练当作每次都要执行的基础测试 |
| `data/` | 数据说明与本地数据位置 | 将数据准备说明与数据读取实现混在一起 |
| `results/` | 精选的公开参考结果 | 不加选择地提交所有试运行产物 |

`test.py` 可能是评估集推理脚本，`tests/` 通常是软件检查，两者用途应在 README 中说清。模型结构代码和模型权重也应区分；目录叫 `models/` 时，明确里面保存哪一种内容。

## 基线与消融需要提供多少

- 自己实现或修改的基线：保留实际实现、配置和来源说明。
- 直接使用第三方官方实现：给出仓库、固定版本或提交号、依赖和运行配置；重新分发代码时保留原许可。
- 消融：用明确配置或参数开关表达被替换的部分，避免为每个变体复制整份训练代码。
- 共享协议：给出固定划分、预算、种子和指标，使读者知道不同方法如何比较。

## 哪些内容提交到 Git

**通常提交：** 源码、配置、运行脚本、环境声明、数据获取说明、必要的小型划分／选样索引、核心检查、图表生成代码和精选参考结果。

**通常另行存放：** 大型原始数据、特征缓存、模型权重、完整训练日志和中间产物。需要它们才能复现时，应给出下载或重建方式、版本与必要的校验信息，不能只写“请自行准备”。

**保留在本地：** 凭据、个人路径配置和工作记录。可以提供不含秘密的配置示例，让读者填入自己的路径。

目录树中的 `data/` 与 `results/` 是职责位置，不代表所有内容都要提交。可以通过 `.gitignore` 选择保留说明和小型参考文件。

## 一次运行应留下什么

建议保存配置、随机种子、代码版本、输入划分或版本标识、验证与测试指标，以及必要的 checkpoint 信息。输出可以按 `数据集/方法/运行标识/` 组织，不需要预先引入实验追踪平台。

预处理统计量应由训练划分确定；使用验证结果选择 checkpoint，测试集用于最终评估。多种子结果要说明汇总顺序，例如先对每个选择子集的训练种子取均值，再对不同选择种子汇总。只提供一个最终均值，难以核对结果来源。

## 发布前的最小验证

- 在干净环境中，按 README 走通一条轻量路径。
- 检查数据与源码路径能由参数或配置指定。
- 核对主实验配置、输出单位和图表统计口径一致。
- 复用核心算法与评价指标的小型检查。
- 检查待提交文件，确认只包含计划发布的内容。

上述是准备发布代码时的建议。本仓库是说明文档，没有附带或执行训练实验。返回[项目首页](../README.md)，或查看[参考模板](references.md)。
